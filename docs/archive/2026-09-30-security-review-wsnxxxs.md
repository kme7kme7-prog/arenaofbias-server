### SR-01 · P1 · 数据包作品可在 API 同源执行

位置：`server/app.mjs:445–451`；相关数据路径来自 `server/catalog.mjs:44`。

`serveSite` 将整个 `config.dist` 作为静态根目录。只有根 `index.html` 得到站点 CSP，`_scenes/.../index.html` 等作品 HTML 原样以 `text/html` 返回，没有作品 CSP sandbox。本地数据包确有这类页面。因此，作品独立域名上的防护可以被 API 静态入口绕过。触发条件是数据包包含恶意作品，且已登录用户在 API 地址下打开它；这不要求读取 HttpOnly Cookie，浏览器会自动给同源请求附带会话。

证据：临时数据包中的 `/_scenes/probe/index.html` 返回 200、`Content-Type: text/html; charset=utf-8`、CSP 为空。在浏览器中登录临时管理员后打开该页面，其脚本 GET `/api/admin/users` 返回 200、读到 1 个临时用户，PATCH `/api/me` 返回 200。只修改了临时账号的昵称。浏览器证据存于本地生成物 `output/audit/security-review-20260930-api-origin.png`，不纳入 Git。

影响：恶意馆藏页面可使用访问者的现有权限；管理员访问时可调用管理 API。作品审核通过不等于允许作品获得 API 同源权限。

最小修复：API 静态入口拒绝作品目录，将作品资源限定在内容源；若需要兼容原资源 URL，应提供明确的隔离或下载行为，不能继续在 API 源提供可执行作品 HTML/SVG。仅给这些页面套当前允许内联脚本的站点 CSP 无法解决同源权限问题。

判定：HTTP 行为及浏览器读写链均已在本地确认；线上代理是否额外屏蔽该路径未核实。

### SR-02 · P1 · 畸形作品请求可退出共享服务

位置：`server/content.mjs:74`；共享进程监听两个端口见 `server/index.mjs:15–16`。

内容请求处理器没有异常边界。有效作品 token 被解析后，直接调用 `new URL(req.url, ...)`；Node HTTP 接受的部分请求目标会被 WHATWG URL 解析器拒绝。异常逃出 HTTP request 监听器，导致进程退出，连带关闭 API 和内容服务。

证据：使用真实 `createContentHandler`、临时目录、固定的有效作品 token 和独立 Node 子进程。三种请求目标 `//[`、`/\[`、`http://[` 均触发 `TypeError: Invalid URL`，堆栈定位 `server/content.mjs:74:26`，子进程 exit=1。没有向生产发送这些请求。

最小修复：内容请求入口捕获 URL 解析错误并返回 400；同时为入口的同步文件读取/目录查找保留局部异常处理，避免同类请求异常退出进程。无需引入新的框架。

判定：直连 Node 的单请求退出已确认。公网是否能传入相同请求目标取决于代理解析及转发方式，本轮没有验证 Nginx。不能把代理可能过滤请求当作应用异常边界。

### SR-03 · P1 · 启用截图时缺少服务器网络边界

位置：`server/capture.mjs:30–37`；相关策略为 `server/content.mjs:36–48`，投稿后即排队见 `server/app.mjs:178`。

截图浏览器直接打开未审核的用户作品，没有导航目标检查、请求拦截或网络隔离。作品的 CSP 限制 fetch/资源加载，但作品作为顶层页面仍能自行导航到另一个地址。因此，当 `CAPTURE=1` 且 Playwright/Chrome 可用时，用户作品可能让服务器浏览器访问环回、内网或云元数据地址。风险判断不依赖截图浏览器拥有管理员 Cookie。

证据：用实际内容处理器施加现有完整 CSP，浏览器打开临时作品；页面通过 `location.replace` 跳转到另一个 `127.0.0.1` 端口。该端口记录 `SINK_HIT=/audit-marker`。浏览器导航等待超时、DOM 未呈现目标正文，因此这项验证只证明目标收到请求，没有证明实际截图成功或内部正文被读取。后台 `createCapturer` 本轮未启用；完整 SSRF/内部页面截图链属于依据代码和导航证据作出的推断。

影响：截图进程可被用于对服务器可达地址发起请求；若目标能渲染且截图成功，生成的作品截图还可能泄露内部页面内容。

最小修复：启用截图前限制该进程的网络访问，仅允许作品源及必要 CDN，并覆盖页面导航和重定向。已有部署若采用 `CAPTURE=0`，维持该设置可避免此条执行路径；本轮没有核实线上开关，也没有修改配置。

标准依据：[W3C CSP connect-src](https://www.w3.org/TR/CSP/#directive-connect-src) 控制 fetch、XHR、WebSocket 等连接接口；其约束不能被当作截图浏览器的全部网络边界。

### SR-04 · P2 · 转发头首项可成为任意限流身份

位置：`server/http.mjs:78–80`；鉴权使用该 IP 限流见 `server/app.mjs:123` 和 `server/app.mjs:131`。

`TRUST_PROXY=1` 时，无条件将 `X-Forwarded-For` 的第一项作为客户端 IP。若边缘代理保留用户原头并追加真实 IP，首项仍由用户控制。轮换首项可绕过登录、邮件等按 IP 的限制，并影响猜模型 IP 去重与访问统计。若代理覆盖头且后端只接收可信代理连接，此风险条件不成立。

证据：在临时 HTTP 服务和数据库中启用 `trustProxy`。同一环回连接来源、固定尾部 `203.0.113.5`，固定首项的 11 次错误登录为 `[401 × 10, 429]`；只轮换首项，11 次全部返回 401，即均进入鉴权而未触发限流。未查询生产代理配置。

最小修复：当前单层代理场景先要求边缘代理覆盖转发头，并限制后端直连；若确需多层代理，再依据明确的可信跳数/地址解析。不要在部署链路未知时简单信任第一项或最后一项。

依据：[Nginx 官方 proxy 模块文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#variables) 明确 `$proxy_add_x_forwarded_for` 会保留客户端头并追加 `$remote_addr`。本轮条件性风险适用于采用这种保留方式的部署，不表示已确认本项目线上采用该配置。

### 已有防护与复核结论

- 管理接口统一检查登录及管理员角色；公开注册拒绝保留管理员名。
- 密码使用 scrypt；会话 token 与导出 token 仅保存哈希。Secure 会话使用 `__Host-` 前缀、HttpOnly，重复会话 Cookie 被拒绝。
- API 写请求校验完整 Origin；可信来源才得到凭据 CORS。恶意同源 HTML 仍会通过来源检查，见 SR-01。
- 收件箱预览响应包含 `sandbox allow-scripts`，没有 `allow-same-origin`；已修复历史的新窗口同源权限问题。
- ZIP 路径、符号链接、重复文件、解压输出量和请求体有约束；没有执行上传内的构建命令。
- 业务 SQL 使用参数绑定；投票/审计等关键状态组合通过事务写入。
- 验证码有过期、错误次数与一次性消费；重置密码撤销全部会话；Turnstile 校验失败或服务不可用时拒绝请求。

本轮没有发现上述检查路径的新越权。所有保护仍需其配置条件成立；没有宣称已做完整渗透测试。
