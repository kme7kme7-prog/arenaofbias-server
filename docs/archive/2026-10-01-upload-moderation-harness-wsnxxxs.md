## 本轮目标

修复截图不可恢复及审核状态不一致，减少作者审核信息暴露，停止收集 Harness 版本。用户最后将私有数据仓配套纳入本轮，授权后端和数据仓各一条英文提交并一起推送；不部署、不切换消费者 pin、不清空数据库存量版本。

## 改动

- 截图启动探测并打印一次能力状态；Playwright 导入或浏览器启动失败后冷却五分钟，由后续新作品重试。每档视口失败使用新 context 重试一次，保留两档截图齐备才送 Luna 的规则。修复恢复测试发现的队列结束时新任务可能搁置问题。
- bootstrap 增加 `site.autoModeration`，由审核开关、密钥和当前截图能力计算；`review.unverified` 限定内容 legacy/approved、作品 unverified 且所属题目公开，`review.content` 仅计 review。未传 viewer 的 catalog 查询仅返回公开社区题目，待审示例直到题目通过才计入核验队列。
- 作者作品及题目 moderation 仅含 status / at，拒绝时附 reason；管理员维持完整结果。普通核验 API 内容未放行时 verified 返回 409，questioned/unverified 不受限。人工通过理由为空时记「人工复核通过」，保留决定、重试审计及竞技场缓存刷新。
- 用户最终确定管理员直传和收件箱 publish:true 属于人工内容审核：登记时写 approved / human、管理员名、「管理员上传」、时间及审计，再核验 verified，不送 Luna，仍可生成截图。仅登记收件箱继续原自动内容审核流程。
- Harness 版本在全部写入路径忽略，停止领域读取及作品、catalog、arena、收录导出、送审文本输出；仅旧版本字段 PATCH/meta 是成功空操作。后台删除版本输入与显示，内容未放行时禁用核验按钮并解释，人工内容通过理由改选填，待办包含人工内容复核。
- 数据仓由配套独立提交更新 intake/provenance 与相关测试、现行文档，新构建不输出版本；旧版本值忽略，已有作品无需改动。后端数据库列、既有迁移与历史投票原始身份快照保留，读取旧快照时剥离版本。契约及部署说明同步。
